# 异世界裂缝查看器｜手机姿态 Demo v0.1

基于用户原有的 `paranormasight-panorama-replica` WebGL2 全景项目精简制作，**沿用原项目的 `bg08_d.png` 和全景投影片元着色器**，新增手机陀螺仪/设备姿态控制。

## 最核心的设计：按住时相对校准

**手机初始垂着、横着、斜着均不要求“先摆正”。** 在按住“观察异世界”按钮时，记录设备当下的姿态（四元数）和画面当下的 yaw/pitch。后续只应用两者之间的相对旋转；松开即冻结画面，再次按下重新计算基准。此方案没有“识别绝对正前方”的假设，避免一开始手机朝下时突然转到地面。

代价：如果手机一开始朝下，首次按下并不会自动展示地面。**按下时展示的永远是之前的画面；只有按下之后的转动才生效**。这是主动选取的交互定义，而非传感器故障。

- 姿态来源是浏览器的 `DeviceOrientationEvent`（通常融合陀螺仪与加速度计等数据），不是纯陀螺仪积分。
- 四元数用于映射三个轴的相对旋转，比简单相减 `alpha/beta/gamma` 更能避免万向节锁和角度 360° 接缝。
- 需要配合 `screen.orientation.angle` 做横竖屏补偿；横竖屏切换时自动重新校准。
- 有 50ms 稳定滤波、俯仰角限制到 ±80°；不包含真正的空间平移（3DoF）。
- 并非绝对定位或“自动对北”，航向仍可能漂移，用户松开/再按下即可重新锚定。

## 手机如何运行（重要：需要 HTTPS）

1. 解压，把整个目录部署到一个 **HTTPS 静态站点**（例如 GitHub Pages 或支持 HTTPS 的私有部署服务）。
2. 用手机 **Safari / Chrome 的普通浏览器页面**访问，不要用微信内置浏览器。
3. 点击“启用方向感应”，iPhone 上授权设备方向。
4. **按住**观察按钮，然后转动手机；**松开**画面固定；再次按住自动校准。
5. 若无感应支持，仍可直接手指拖动全景。

注意：在电脑上用 `python3 -m http.server 5173` 后，通过 `http://电脑局域网IP:5173` 在手机访问，虽然 WebGL 可能能显示，**但移动浏览器的传感器一般要求安全上下文**，因此很可能读不到。`localhost` 例外仅对运行服务的那台设备成立，不能用来替代手机上的 HTTPS。

电脑本地可运行：

```bash
cd 异世界裂缝查看器_GyroDemo_v0.1
python3 -m http.server 5173
# 打开 http://localhost:5173
```

可在 Chrome DevTools 的 Sensors 面板模拟设备方向，或用项目内提供的 `window.gyroDemo.debugFeed(...)` 进行回归测试。

## 验收动作

| 场景 | 预期结果 |
|---|---|
| 手机低头/朝下，第一次按住 | 画面不跳变，仍显示当前初始方向 |
| 按住后手机向右/左转 30° | 场景观察方向相应转动，不发生突跳 |
| 按住后手机抬高/压低 | 场景俯仰改变 |
| 手机松开又转回起始位置 | 画面冻结不变 |
| 重新按住 | 从当前画面继续，零瞬间跳变 |
| 手机在按住时切换横竖屏 | 自动重新锚定，不因坐标系改变猛烈跳转 |
| 回正按钮 | 回到默认朝向 |
| 浏览器拒绝权限 | 明确告知错误，手指拖动仍可用 |

## 项目结构

- `index.html` / `styles.css`：手机 UI
- `app.js`：从原 WebGL2 实验派生的全景渲染和按住操作
- `gyro.mjs`：设备姿态事件、权限、按住/松开、滤波、横竖屏重校准
- `gyro-math.mjs`：独立可测试的四元数数学
- `assets/bg08_d.png`：原项目全景资产
- `tests.mjs`：无浏览器依赖的姿态数学测试

执行测试：`node tests.mjs`。
